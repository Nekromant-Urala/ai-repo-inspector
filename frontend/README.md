# Фронтэнд AI-Repo Inspector

Angular 19, TypeScript, Reactive Forms и RxJS. Реализованы страницы отправки проекта, ожидания, отчёта и 404.

## Локальный запуск

Из каталога `frontend`:

```sh
npm ci
npm start
```

Приложение открывается на `http://localhost:4200`. Запросы `/api` проксируются на `http://127.0.0.1:8080`; бэкенд должен быть запущен отдельно по инструкции корневого README.

Другой порт:

```sh
npm start -- --host 127.0.0.1 --port 4201
```

Production-сборка:

```sh
npm run build
```

Результат: `dist/ai-repo-frontend/browser/`. Dockerfile фронтэнда раздаёт эту папку через Nginx. Ожидание ответа анализа в Nginx увеличено до 600 секунд.

## Доступные сценарии

- Публичная HTTPS-ссылка GitHub/GitLab → создание проверки → ожидание `run` → отчёт по модулям.
- Выбор/перетаскивание архива с проверкой расширения и размера; серверная загрузка пока недоступна.
- Добавление/редактирование/удаление критериев; серверная обработка критериев пока недоступна.
- Обработка ошибок и уточнение статуса без автоматического повторного запуска анализа.

В `src/app/core/check.models.ts` находятся флаги `CHECK_FEATURES`. Сейчас `archiveUpload` и `customCriteria` выключены: формы объясняют ограничения, а неподдерживаемые запросы не отправляются.

Перед включением этих возможностей бэкенд должен реализовать следующие контракты:

- `POST /api/checks/archive`: multipart-загрузка с частью `file` и необязательной JSON-частью `customCriteria`; ответ — `CheckResponse`, далее выполняется обычный `POST /api/checks/{id}/run`.
- Необязательное поле `customCriteria` в JSON-запросе `POST /api/checks`. Каждый критерий содержит строки `name`, `scale`, `description`.
- Приём и обработку критериев на сервере, а также поддержку заявленных форматов и лимита загрузки архива. Для включения результата кастомного критерия в `criteria[]` его оценка должна соответствовать общей шкале 0–100.

После обновления страницы готовый отчёт восстановить нельзя: текущий сервер не хранит его для повторного получения.

## Ручная проверка

После изменения кода выполнить `npm run build`, затем вручную проверить основной сценарий в браузере: ссылку, ожидание и вывод отчёта. При изменении соответствующих частей проверить валидацию, окно критериев и ошибки сервера. Полный цикл анализа проверять с настоящим бэкендом.
